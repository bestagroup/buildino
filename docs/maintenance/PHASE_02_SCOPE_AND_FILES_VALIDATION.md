# گزارش فاز ۲: Scope و مدیریت امن فایل

تاریخ: 2026-08-16

## دامنه تغییر

- فهرست هزینه، درآمد، اسناد و صورتجلسات به permission و Scope ساختمان محدود شد.
- ایجاد رکورد فقط در ساختمان مجاز امکان‌پذیر است.
- `building_id` و target سند پس از ایجاد قابل جابه‌جایی نیستند.
- `created_by` صرفاً از کاربر احرازشده تعیین می‌شود.
- API سند فقط aliasهای `building` و `unit` را می‌پذیرد و class name دلخواه رد می‌شود.
- route-model binding چهار کنترلر عملیاتی اصلاح شد.
- آپلود فایل خصوصی برای سند و صورتجلسه اضافه شد.
- فایل‌ها با UUID، checksum، محدودیت نوع/حجم و نام ذخیره‌شده مستقل نگهداری می‌شوند.
- path، disk، checksum و metadata داخلی در پاسخ API افشا نمی‌شوند.
- دانلود نیازمند permission و Scope مرتبط است و در `file_downloads` ثبت می‌شود.
- فایل منقضی، آلوده یا بررسی‌نشده قابل دانلود نیست.
- اتصال ClamAV با `clamdscan` فراهم شد و اسکن در production اجباری است.
- Swagger/Postman از multipart upload و شناسه UUID فایل پشتیبانی می‌کند.

## ماتریس تست عملکردی

| تست | انتظار |
|---|---|
| فهرست مالی مدیر ساختمان | فقط رکوردهای ساختمان مجاز |
| ایجاد هزینه در ساختمان خارج Scope | `403` |
| انتقال درآمد/صورتجلسه به ساختمان دیگر | `422` |
| target دلخواه برای سند | `422` |
| مشاهده سند ساختمان دیگر | عدم حضور در collection یا `403` |
| آپلود PDF مجاز | `201` و ذخیره private |
| آپلود PHP/نوع غیرمجاز | `422` |
| آپلود روی سند خارج Scope | `403` |
| دانلود فایل خارج Scope | `403` |
| دانلود فایل منقضی | `410` |
| دانلود فایل آلوده/غیر clean | `423` |
| دانلود موفق | `200` و ثبت audit |
| حذف فایل مجاز | `204`، soft-delete رکورد و حذف بایت |

## اجرای تست

```bash
composer install
composer test:phase2
php artisan api:contract:export
npm install
npm run build
composer release
```

در Windows PowerShell نیز همین دستورات در ریشه پروژه اجرا می‌شوند. پیش از
production باید `FILE_SCAN_ENABLED=true` باشد و `clamdscan` برای کاربر PHP
قابل اجرا باشد.

## محدودیت محیط تولید snapshot

محیط ساخت این snapshot فاقد PHP و Composer است؛ بنابراین تست‌های Feature در
آن اجرا نشده‌اند. صحت JSON، JavaScript، شمارش قرارداد API، ساختار ZIP و اسکن
فایل‌های حساس به‌صورت ایستا کنترل شده است. اجرای `composer test:phase2` روی
CI یا محیط توسعه دارای PHP 8.2+ معیار پذیرش نهایی این فاز است.
